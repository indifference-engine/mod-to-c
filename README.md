## Limitations

### Correctness and extensions to the MOD format

The MOD file format developed as a result of a largely number of developers
building upon one anothers' work without a true specification making explicit
and unambiguous its structure and meaning.  In a way, the existing
implementations (plural) **are** the specification, but they don't fully align
with one another.

As a consequence it is difficult to say with any certainty whether this
implementation is correct.  The following resources were used as reference:

- [The Amiga MOD Format by Norman Lin](https://www.ocf.berkeley.edu/~eek/index.html/tiny_examples/ptmod/ap12.html).
- [The OpenMPT Manual](https://wiki.openmpt.org/Manual:_Effect_Reference).
- [Notes on MOD by Andrew Plotkin](https://eblong.com/zarf/blorb/mod-spec.txt).

The MOD files used for testing were created using
[OpenMPT](https://openmpt.org/).

### Test Coverage

While there is basic test coverage for this utility, error cases currently lack
test coverage.  Details on these missing test cases can be found in the
[issue tracker](https://github.com/indifference-engine/mod-to-c/issues).

## Building

Execute `make` to build the executable, which will be placed at
[dist/mod_to_c](./dist/mod_to_c).

### Dependencies

- Make.
- MinGW-GCC for Windows, Clang for all other platforms.
- Bash.

## Tests

Execute `make test` to run the test suite.
